# TaskRows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri 2 Windows desktop app that shows all Google Tasks lists from up to three Google accounts in draggable rows of side-by-side lists on a portrait monitor, with two-way sync.

**Architecture:** Rust owns OAuth (PKCE + loopback), Windows Credential Manager storage and JSON file persistence, exposed as Tauri commands. The React frontend talks to the Google Tasks REST API directly with `fetch`, keeps all state in one Zustand store fed by a polling sync engine, and renders a board of rows → slots (a slot is one list or a merged same-name group) → tasks. All layout and merge logic is in pure, unit-tested reducers.

**Tech Stack:** Tauri 2 (Rust stable-msvc, `reqwest`, `keyring`, `sha2`, `base64`, `rand`, `serde_json`, `tokio`, `url`, `thiserror`; dev: `wiremock`, `tempfile`), Vite + React 18 + TypeScript, Zustand, `@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/utilities`, Tauri plugins `opener`, `window-state`, `autostart`; Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-23-taskrows-design.md`

- Defaults: list width 320 px; poll interval 60 s (min 15); completed window 30 days; full list refresh every 10th poll; max 3 accounts.
- RAM acceptance: whole process group under 150 MB idle with ~10 lists.
- Thai text must render; font stack `"Segoe UI", "Leelawadee UI", system-ui, sans-serif`.
- Git: repo at `C:\Users\kimra\CodingProject\taskrows`, branch `develop`. Stage explicit paths (never `git add -A`). Never `--no-verify`. Every commit message ends with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **Due dates in Bangkok time.** Google `due` is `YYYY-MM-DDT00:00:00.000Z`; converting via `new Date()` shifts it a day at +07:00. Expect the date shown and saved to equal the date picked. Test in Task 4 (`dates.test.ts`).
2. **Offline at launch.** No network: board renders from `cache.json`, footer says offline, writes are disabled, no crash or error spam. Test in Task 8 (`syncEngine.test.ts`).
3. **One account's refresh token revoked.** `invalid_grant` on refresh marks that account "needs sign-in" and the other accounts keep syncing. Test in Task 3 (Rust `token.rs`) and Task 8 (engine isolates per-account errors).
4. **Quota or rate-limit (HTTP 429/403 `rateLimitExceeded`).** Polling backs off (interval doubles up to 10 min), one toast, recovers on next success. Test in Task 8.
5. **Long or Thai titles.** Titles wrap inside the fixed list width, never truncated or overflowing the column. Test in Task 10 with a 120-char Thai title.

- Produces (`syncEngine.ts`):
  ```ts
  export interface Clock { now(): number; setTimeout(fn: () => void, ms: number): unknown; clearTimeout(h: unknown): void }
  export class SyncEngine {
    constructor(store: StoreApi<State & Actions>, api: TasksApi, clock: Clock = realClock)
    start(): Promise<void>   // per account: listTaskLists → setLists; per list: listTasks({ completedMin: now−30d }) → applyListTasks(full=true); then writesEnabled=true, phase 'idle', schedule next
    stop(): void
    syncNow(): Promise<void> // incremental: per account listTaskLists; skip a list whose `updated` is unchanged since last cycle; else listTasks({ updatedMin: lastSync−5min, showDeleted: true }) → applyListTasks(full=false); every 10th cycle runs the full fetch instead
    pause(): void; resume(): void   // minimized / restored; resume() calls syncNow()
  }
  ```
